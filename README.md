# 真实日记（real_diary）

**把「当天真实发生过的事」写成日记，而不是编一个。**

这个插件每天替你回顾一次：把散在各个插件里的记忆碎片收拢起来，用指定模型写成
一篇第一人称的日记，落到你指定的目录。它只做三件事：

1. **采集**：归档摘要、每日短期记忆、记忆条目、状态阶段、时间事实 → 全落进
   `data/json_storage/real_diary/day-YYYY-MM-DD`；
2. **生成**：跨天时（启动检查 + 每天 02:00 检查）问一句「昨天的日记写了没」，
   没写就调模型补上，写到 `<实例根>/data/diary/YYYY-MM-DD.md`；
3. **清理**：日记落盘成功后，**只删自己抓来的素材碎片**——
   booku 记忆库、`context_archiver` 索引、任何外部数据，一个字都不动。

---

## 它解决什么问题

Bot 的「今天」是散装的：

| 谁 | 记了什么 | 缺什么 |
| --- | --- | --- |
| `context_archiver` | 每次话题结束的摘要 + 记忆条目 | 没有「一天」这个维度，200 条审计一满就滚掉了 |
| `send_to` / `cross_stream_relay` | 每个群的**当天**短期记忆 | 一天一条、只有摘要，没有串成一段回忆 |
| `booku_memory` | 可检索的记忆库 | 没有日期字段，不知道哪条是哪天的 |
| `sisp` / `deep_neo_sisp` | **当前**阶段 | 不保留历史，翻页了就没了 |
| `time_sense` | 准确的时间事实 | 它不认识「日记」，只回答几点、多久 |

碎片都在，但没有人在**当天结束之后**把它们收拢、去伪、写成一段连贯的回忆——
本插件就是那个收拢的人。

它和 `daily_schedule` 的离线日记是**互补**关系，不是重复：
后者记的是「**她不在线时**我把那段时间缝成什么」，本插件记的是
「**她在场时真实经历了什么**」。

## 它怎么工作

```
【采集】
  context_archiver 归档成功 ──事件──►┐
  context_archiver 审计/记忆索引 ─巡检─┤
  send_to / cross_stream_relay ─巡检──┼─► 素材碎片
  sisp 状态快照 ─消息事件采样比对─────┤   data/json_storage/real_diary/day-YYYY-MM-DD
  time_sense / 系统时钟 ─────────────┘

【生成】启动时 + 每天 02:00（幂等）
  读「昨天」素材
    ├─ 没素材 ──────────────► 不写（空着也不编）
    ├─ 素材残缺 / 超回补窗口 ─► 丢弃、不写（**不虚构**）
    └─ 够写 ─► 组装 prompt ─► 指定模型 ─► 清洗 ─► 原子写盘
                                                  │
                  素材碎片删除 ◄── 登记 done ◄─────┘（写成功才走到这里）
```

### 三条通路为什么都需要

- **事件**：归档一成功就收，这是「立即」；
- **巡检**：事件会丢（进程没在、崩溃），巡检兜底把「今天/昨天」再抓一遍；
- **启动检查**：崩溃跨天、凌晨关机都不会漏——**判据只有一个**：`done` 里有没有那天。

### 为什么「不虚构」是硬口径

崩溃三天后重启时，那三天的素材必然是残缺的（进程根本没在写）。这时候
「用现有素材编一篇完整的日记」是最坏的选择——读者（也就是你）不知道哪些是真的。
所以本插件的做法是：

- `backfill_days`（默认 1）**窗口之外的日子**：素材直接丢弃，**不生成**；
- 窗口内但素材残缺（条数太少 / 中间空了一大段）：照写，但正文里**如实说明**
  「这一天我记得不太全」，文件末尾的注释也会标 `完整度：不完整`。

## 快速开始

**第一步：先只观察（默认就是）。**

```toml
[plugin]
mode = "observer"     # 默认值：只采集、只打日志，不写任何文件
```

放一天，然后：

```
/日记 状态        # 收了多少素材、昨天写了没
/日记 素材        # 看昨天到底收了些啥（这一步最重要）
```

**第二步：看看它打算写成什么样。**

```
/日记 演练        # 只调模型看正文，不落盘、不删素材
```

不满意就调 `[generate]` 与 `[model]`，再演一次。

**第三步：确认没问题再开写。**

```
/日记 active      # 只改运行时，重启回到配置文件的值
```

或者在 `config.toml` 里把 `plugin.mode` 固化成 `active`。

**第四步（可选）：接住「归档即联动」。**

如果你装了 `context_archiver`（1.3.0+），它归档成功会广播
`context_archiver:archived`，本插件默认订阅它——**素材是实时入库的**，
不用等巡检。关掉的话也不会漏，只是晚一步（`collect.archive_events = false`）。

## 命令

仅主人可用（会触发真实模型调用与文件写入）。

```
/日记                    状态总览
/日记 状态 /status       同上
/日记 素材 [日期]         某天的素材清单（核对质量用）
/日记 演练 [日期]         只调模型看正文，不落盘
/日记 现在 [日期]         立刻生成（默认昨天）
/日记 重写 [日期]         抹掉留档后重新生成（会覆盖原文件）
/日记 丢弃 [日期]         丢弃某天素材，不生成
/日记 检查               跑一次幂等检查（缺就补）
/日记 observer|active    切换运行模式（只改运行时）
/日记 帮助
```

日期可以写 `2026-10-14`，也可以写「今天 / 昨天」；留空 = 昨天。

## 配置

配置文件：`config/plugins/real_diary/config.toml`（首次加载自动生成）。

### `[plugin]`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关（关闭后组件整体下线） |
| `mode` | `observer` | `observer` 只采集；`active` 才真的写日记 |
| `debug_log` | `false` | 每条素材、每次决策都打日志 |
| `diary_dir` | `""` | **留空 = `<实例根>/data/diary/`**；也可填绝对路径 |

### `[collect]`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `archive_events` | `true` | 订阅 `context_archiver:archived`（归档即收） |
| `daily_memory` | `true` | 采 `send_to` / `cross_stream_relay` 的每日短期记忆 |
| `memory_index` | `true` | 采 `context_archiver` 的记忆索引（按 `at` 切天） |
| `audit_timeline` | `true` | 采归档审计（「那天归档了什么」） |
| `booku_digest` | `false` | 直接从 booku 记忆库拉（**默认关**：无时间范围查询，重复劳动） |
| `state_phases` | `true` | 采样状态阶段（读快照 + 自己比对） |
| `sisp_stores` | `["sisp", "deep_neo_sisp"]` | 状态快照的命名空间，按顺序试 |
| `poll_seconds` | `300` | 巡检兜底间隔 |
| `max_items_per_day` | `400` | 单日素材上限（超了丢最旧的并留一条说明） |
| `max_item_chars` | `1200` | 单条素材正文上限 |

### `[generate]`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `check_on_start` | `true` | 启动时检查昨天（**主通路**，不依赖定时器） |
| `check_time` | `"02:00"` | 运行期每天第二次检查的时点；留空 = 只在启动时查 |
| `backfill_days` | `1` | 允许往回补几天；**超窗口的丢弃、不生成** |
| `min_items` | `3` | 少于这么多条 = 素材不完整 |
| `gap_max_hours` | `6.0` | 相邻素材间隔超过它 = 中间没记录 → 不完整 |
| `coverage_min_hours` | `2.0` | **有记录的时间跨度**不足这么长 → 不完整（防止「只有晚上一小时有记录」被当成完整的一天；`0` = 关掉这条） |
| `max_prompt_chars` | `16000` | 喂模型的素材上限（超了先丢低优先级、更早的流水） |
| `retry_backoff_seconds` | `300` | 失败退避（失败不删素材、不登记，退避到点再试） |

### `[model]`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `task_name` | `"summary"` | 用哪个模型任务（实例没配就回落到 `actor`） |
| `model_name` | `""` | 直接点名模型（非空时优先） |
| `temperature` | `0.6` | 写日记的温度（比总结高一点，别太高免得出戏） |
| `max_tokens` | `8192` | **必须给思考模型留足**，否则正文没机会输出（`empty response`） |

### `[output]`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `file_format` | `"{date}.md"` | 文件名模板 |
| `title_format` | `"# {date}"` | 首行标题模板（`{date}` / `{weekday}`） |
| `write_meta_line` | `true` | 文末附一行元信息（素材数 / 模型 / 完整度） |
| `incomplete_note` | `"（这一天我记得不太全）"` | 素材不完整时追加的如实声明 |

### `[cleanup]`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `delete_fragments` | `true` | 落盘成功后删掉当天的素材碎片（**只删自己的**） |
| `keep_done_records` | `400` | `done` 留档保留多少天 |

### `[storage]`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `namespace` | `real_diary` | 多 Bot 共用 data 目录时用来隔离 |

## 数据落盘

```
data/json_storage/real_diary/
  day-YYYY-MM-DD    # 素材碎片（日记写完后删）
  done              # 已生成日记的日期留档（路径/素材数/模型/完整度/碎片删没删）
  runtime           # 运行水位（上次巡检/上次生成/失败计数/阶段基线）

<实例根>/data/diary/YYYY-MM-DD.md   # 日记本体
```

删掉 `done` = 它会认为那些日子都没写过（下次检查会重写一遍）；
删掉 `runtime` = 阶段基线丢失，下次采样会把「当前阶段」重新记一遍（无害）。

## 边界与取舍（诚实版）

**1. 状态阶段采不全，这是 sisp 的现状不是本插件的 bug。**
`sisp` / `deep_neo_sisp` 都**不发布阶段转变事件、也不保留转变历史**（只有当前值
两个 JSON）。所以本插件只能「读快照 + 自己比对」——**没有消息的时段采不到**，
阶段可能在你没被调用的时间里自己翻页了。日记里只写「我观察到什么」，不推断中间过程。

**2. 每日短期记忆是滚动的。**
`daily_memory_<流>_<日期>.json` 会被后续总结**改写**。本插件靠巡检与事件**增量采快照**，
所以你看到的是「不同时刻看到的那一份」；同一天里两个 store 都有时，取
`last_summarized_ts` 更新的那份。

**3. 素材索引是有界表。**
`context_archiver` 的 `audit` 只留 200 条、`memory_index` 只留 800 条。
繁忙实例里旧数据会被顶掉——所以本插件**必须自己按天落盘**，不能指望事后回头翻。

**4. 事件可能丢。**
归档事件在进程没跑、或订阅者报错时收不到；本插件的对策是巡检 + 启动检查兜底，
但**半天没记录**这种情况仍会被判「素材不完整」并如实标注。

**5. 生成失败不会丢素材。**
失败时不删素材、不登记 `done`，退避 60→…→1800s 重试。所以一次模型抖动不会
让那天彻底没有日记。

**5.5 模型偶尔会用「安静」填补没记录的时间——这件事被盯住了。**
判据能拦住「只有一小段有记录」的日子（`coverage_min_hours`），prompt 里也明确禁止
（还专门举了例子），但模型仍可能换个说法——2026-10-16 的虚拟真机测试里它连写两次
「白天群里没什么动静」。所以加了两道：

- **如实声明挪到正文之前**：不完整的日子，标题下第一行就是「（这一天我记得不太全）」，
  读到正文前你就知道这不是全貌；
- **事后体检**：正文命中「白天很安静 / 一整天平平淡淡」这类句式时，文件末尾注释会标
  `⚠ 疑似补白（正文提到没记录的时间）`，日志同步打 WARNING。

拦不住百分百，但至少**不假装它没发生**。

**6. 多 Bot 共用一个 data 目录时**要配不同的 `storage.namespace`
（同 `time_sense` / `context_archiver` 的约定）。

**7. 隐私**：素材碎片与日记正文都可能含私聊内容。生成成功后碎片会被删掉
（`delete_fragments`），日记本体请放在你自己认为安全的位置
（`plugin.diary_dir` 可以指到任何地方）。

**8. 私聊素材的「视角」在源头就丢了——这是最需要知道的一条。**
`[归档]`（`context_archiver` 的摘要）是**客观第三人称**记录，提到她时写的是「bot」；
`[我的回忆]`（`daily_memory`）是**她自己视角**的第一人称回忆；
但 `[记忆]`（`memory_index` 的片段）**来自记忆库，总结时没保留「谁说的」**——
「我家爱弥斯…」这种句子到了日记这边，无法判断是你说的话还是她的回忆。

本插件对此的处理是**保守**：提示词里明确「[记忆] 里的『我』通常指对方，看不清就略过」，
于是这类素材经常**整段不写**。**少写 ≠ 编造**——按「不虚构」优先，
这是刻意选的方向。想要私聊细节也进日记，得从上游补（让 `context_archiver` 写记忆时
保留说话人标记），或者干脆把 `collect.memory_index` 关掉换取干净。

**9. 残留的成员代号只能「标出来」，拦不干净。**
提示词明确禁止输出纯数字（如 `482063`），但模型偶尔仍会抄一两个。事后体检
`spot_bare_ids()` 会在元信息行标 `⚠ 含 N 处裸数字`——**不自动删**，因为
「143390 分」也是数字，误删真数据比漏标更糟。

## 跟已有插件的关系

| 插件 | 关系 | 缺席时 |
| --- | --- | --- |
| `context_archiver` | 素材主力（归档事件 + 审计 + 记忆索引） | 少一大路素材，仍可用每日短期记忆 |
| `send_to` / `cross_stream_relay` | 现成的「按天一条」摘要 | 只靠归档与状态素材 |
| `time_sense` | 时间事实与账本 | 用进程墙钟；日期口径不变（本地自然日） |
| `sisp` / `deep_neo_sisp` | 状态阶段素材 | 日记少「状态」那一路 |
| `booku_memory` | 可选的直接记忆源 | 无影响（默认本来就没开） |

**全部是运行时探测的软依赖**：`manifest.json` 的 `dependencies.plugins` 一律留空
——框架对「声明了却不可用」的依赖是**硬剔除**，`dependencies_required: false`
救不回来。所以缺谁都能跑，只是素材少一路。
